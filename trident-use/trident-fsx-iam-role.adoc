= Crea un ruolo IAM e un segreto di AWS Secrets Manager
:hardbreaks:
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Puoi configurare i pod Kubernetes in modo che accedano alle risorse AWS autenticandosi come ruolo AWS IAM invece di fornire credenziali AWS esplicite.


NOTE: Per autenticarti usando un ruolo AWS IAM, devi disporre di un cluster Kubernetes implementato con Amazon EKS o Red Hat OpenShift.



[[create-an-aws-secrets-manager-secret]]
== Creare un segreto AWS Secrets Manager

Trident necessita di credenziali per gestire lo storage sulla SVM FSx for ONTAP. Archivia le `vsadmin` credenziali in un segreto di AWS Secrets Manager.

Questo esempio crea un segreto di Gestore segreti AWS per memorizzare le credenziali Trident CSI:

[source, console]
----
aws secretsmanager create-secret --name trident-secret --description "Trident CSI credentials" \
  --secret-string "{\"username\":\"vsadmin\",\"password\":\"<svm_password>\"}"
----


[[create-an-iam-policy]]
== Crea una policy IAM

Trident necessita anche delle autorizzazioni AWS per funzionare correttamente. Pertanto, è necessario creare un criterio che fornisca a Trident le autorizzazioni necessarie.

L'esempio seguente crea una policy IAM utilizzando l'AWS CLI:

[source, console]
----
aws iam create-policy --policy-name AmazonFSxNCSIDriverPolicy --policy-document file://policy.json \
  --description "This policy grants Trident CSI access to FSx for ONTAP and AWS Secrets Manager" \
  --query Policy.Arn --output text
----
Il comando restituisce l'ARN della policy. Utilizzalo nei seguenti comandi.

*Policy JSON esempio*:

[source, json]
----
{
  "Statement": [
    {
      "Action": [
        "fsx:DescribeFileSystems",
        "fsx:DescribeVolumes",
        "fsx:CreateVolume",
        "fsx:RestoreVolumeFromSnapshot",
        "fsx:DescribeStorageVirtualMachines",
        "fsx:UntagResource",
        "fsx:UpdateVolume",
        "fsx:TagResource",
        "fsx:DeleteVolume"
      ],
      "Effect": "Allow",
      "Resource": "*"
    },
    {
      "Action": "secretsmanager:GetSecretValue",
      "Effect": "Allow",
      "Resource": "arn:aws:secretsmanager:<aws-region>:<aws-account-id>:secret:<aws-secret-manager-name>*"
    }
  ],
  "Version": "2012-10-17"
}
----


[[create-an-iam-role-for-pod-identity-or-an-iam-role-for-a-service-account-irsa]]
=== Crea un ruolo IAM per Pod Identity o un ruolo IAM per un service account (IRSA)

Puoi configurare un account di servizio Kubernetes in modo che assuma un ruolo AWS Identity and Access Management (IAM) con EKS Pod Identity o con i ruoli IAM per gli account di servizio (IRSA). I pod configurati per utilizzare l'account di servizio possono quindi accedere ai servizi AWS a cui il ruolo è autorizzato ad accedere.

[role="tabbed-block"]
====
.Identità del pod (EKS)
--
Le associazioni di identità dei pod Amazon EKS offrono la possibilità di gestire le credenziali per le applicazioni, in modo simile a come i profili delle istanze Amazon EC2 forniscono le credenziali alle istanze Amazon EC2.

*Installa Pod Identity sul tuo cluster EKS*:

Puoi creare l'identità del Pod tramite la console AWS o utilizzando il seguente comando AWS CLI:

[listing]
----
aws eks create-addon --cluster-name <EKS_CLUSTER_NAME> --addon-name eks-pod-identity-agent
----
Per ulteriori informazioni, consulta link:https://docs.aws.amazon.com/eks/latest/userguide/pod-id-agent-setup.html["Configurare l'agente di identità del pod Amazon EKS"].

*Crea trust-relationship.json*:

Crea trust-relationship.json per consentire al Service Principal EKS di assumere questo ruolo per l'identità del Pod. Quindi crea un ruolo con questa policy di attendibilità:

[listing]
----
aws iam create-role \
  --role-name fsxn-csi-role --assume-role-policy-document file://trust-relationship.json \
  --description "fsxn csi pod identity role"
----
*file trust-relationship.json*:

[source, json]
----

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Service": "pods.eks.amazonaws.com"
      },
      "Action": [
        "sts:AssumeRole",
        "sts:TagSession"
      ]
    }
  ]
}
----
*Associare la policy del ruolo al ruolo IAM*:

Associa il criterio di ruolo del passaggio precedente al ruolo IAM creato:

[listing]
----
aws iam attach-role-policy \
  --policy-arn arn:aws:iam::aws:111122223333:policy/fsxn-csi-policy \
  --role-name fsxn-csi-role
----
*Crea un'associazione di identità pod*:

Crea un'associazione di identità del pod tra il ruolo IAM e l'account di servizio Trident (`trident-controller`).

[listing]
----
aws eks create-pod-identity-association \
  --cluster-name <EKS_CLUSTER_NAME> \
  --role-arn arn:aws:iam::111122223333:role/fsxn-csi-role \
  --namespace trident --service-account trident-controller
----
--
.Ruolo IAM per gli account di servizio (IRSA) (solo EKS)
--
*Utilizzando l'AWS CLI*:

[listing]
----
aws iam create-role --role-name AmazonEKS_FSxN_CSI_DriverRole \
  --assume-role-policy-document file://trust-relationship.json
----
*file trust-relation.json:*

[source, json]
----
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Federated": "arn:aws:iam::<account_id>:oidc-provider/<oidc_provider>"
      },
      "Action": "sts:AssumeRoleWithWebIdentity",
      "Condition": {
        "StringEquals": {
          "<oidc_provider>:aud": "sts.amazonaws.com",
          "<oidc_provider>:sub": "system:serviceaccount:trident:trident-controller"
        }
      }
    }
  ]
}
----
Aggiornare i seguenti valori nel `trust-relationship.json` file:

* *<account_id>* - ID del tuo account AWS
* *<oidc_provider>* - L'URL del provider OIDC per il tuo cluster EKS. Puoi ottenerlo eseguendo:
+
[source, console]
----
aws eks describe-cluster --name my-cluster --query "cluster.identity.oidc.issuer" \
  --output text | sed -e "s/^https:\/\///"
----


*Associa la policy IAM al ruolo IAM*:

Una volta creato il ruolo, allegare il criterio (creato nel passaggio precedente) al ruolo utilizzando questo comando:

[source, console]
----
aws iam attach-role-policy --role-name my-role --policy-arn <IAM policy ARN>
----
*Verifica l'associazione del fornitore OIDC*:

Verifica che il tuo provider OIDC sia associato al cluster eseguendo questo comando:

[source, console]
----
aws iam list-open-id-connect-providers | grep $oidc_id | cut -d "/" -f4
----
Se l'output è vuoto, utilizzare il seguente comando per associare IAM OIDC al cluster:

[source, console]
----
eksctl utils associate-iam-oidc-provider --cluster $cluster_name --approve
----
Se stai utilizzando `eksctl`, usa il seguente esempio per creare un ruolo IAM per un account di servizio in EKS:

[source, console]
----
eksctl create iamserviceaccount --name trident-controller --namespace trident \
  --cluster <my-cluster> --role-name AmazonEKS_FSxN_CSI_DriverRole --role-only \
  --attach-policy-arn <IAM-Policy ARN> --approve
----
--
.Ruolo IAM per l'autogestione di OpenShift
--
L'implementazione autogestita di OpenShift crea ruoli IAM e li associa ai nodi del cluster. Associa la policy IAM di Trident al ruolo assegnato a ciascun nodo.

Per trovare gli ID delle istanze dei nodi nel tuo cluster, esegui il seguente comando:

[source, console]
----
oc get nodes -o jsonpath='{range .items[*]}{.spec.providerID}{"\n"}{end}'
----
Per trovare il ruolo IAM associato a ciascuna istanza, esegui il seguente comando per ogni istanza:

[source, console]
----
aws ec2 describe-instances --instance-ids <instance-id> --query 'Reservations[*].Instances[*].IamInstanceProfile.Arn' --output text
----
Associa la policy IAM a ciascun ruolo eseguendo il seguente comando:

[source, console]
----
aws iam attach-role-policy --role-name <role-name> --policy-arn <IAM policy ARN>
----
